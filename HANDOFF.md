## Следующий шаг: задания на рассуждение (предложение, не начато)

Вместо «найди фразу» писать задания, ответ на которые следует из книги, но не лежит в тексте готовой фразой:
1. **Предсказание:** «что произойдёт с показаниями, если…». Условие и ответ строятся из правил автора (claims вида «если A, то B»; поля узла «где ломается» и «что значит для данных»). Неверные варианты: противоположное направление и формулировки заблуждений из `domain-pack/geology/misconceptions.json` (tier=core) через `misconception_map.json` (узел → заблуждение, пояснение = `book_quote`).
2. **Перенос / выбор метода:** «какой метод/правило применить при условиях …» по условиям применимости (claims с kind=допущение, `physics_checklist.json`).
3. **Расчёт с другими числами:** формула из утверждений слоя, числа изменены относительно примера книги; ответ вычисляет сборщик (как калькулятор), расхождения с книгой не маскируются.
4. **«Найди ошибку»:** показать неверное утверждение (из core-заблуждений) и выбрать, почему оно неверно.
Правила: у каждого задания ключ с цитатой и страницей; ни один ответ не опирается на знания модели вне книги; задания про условия, где книга оговаривается, помечать «по автору»; задания типа «перенос» показать ментору. Критерий готовности: в повторном новичок-тесте доля «поиска фразы» ≤ 50%, у каждого шага со смыслом есть задание, ключи не расходятся с книгой. Реализация: расширить обвязку заданий (`tasks` в `tools/course_config/*.json`) либо генератор заданий из слоя; сборщик `tools/build_course.py` проверяет, что ответ дословно есть в утверждениях, для новых типов проверку нужно описать отдельно (расчёт — пересчётом, предсказание — по паре утверждений).

## Что надо помнить (ловушки)

- Курсы читают **общий** `build/latyshova/nodes.json`, а не разделы. После правки любого `sections/*/nodes.json` сначала `make org CHAPTER=latyshova` (или `merge_layer.py`), потом пересобирать курсы. Я один раз собрал курс из устаревшего слоя и потерял на этом время.
- Блоки `FORMAT` и `figure_desc` в `clean.md` — описания рисунков от модели, не слова автора и часто ошибочны. Числа, индексы и знаки читать по скану (`pdftoppm -f N -l N -r 200 -png chapters/latyshova/latyshova.pdf /tmp/...`). Номера страниц = PDF-страницы.
- Цитата в слое должна быть дословной и на своей странице (`check_nodes`); в слое организаторов цитата проверяется по ИСХОДНОМУ md (`chapters/latyshova/train_latyshova.md`), где на ряде страниц OCR-транслитерация.
- Правки слоя агентами: скан обязателен для чисел, индексов, знаков (`tools/prompts/fix_r2.md`).
- Тесты в Chromium: `require('playwright')`, `NODE_PATH=$(npm root -g)`, окно 390×800; тестеру запрещено читать конфиги курсов и встроенный JSON страницы (там ключи).
- Охранная проверка Claude Code может отклонить длинную составную bash-команду с heredoc, даже без удаления; в таком случае записать скрипт в файл и запустить отдельной командой.
- Не называть файлы чьим-либо именем автоматически; поля имени оставлять пустыми для ввода пользователем.
