# Проверка заданий курса (verifier), несколько разделов
Подставляется: CHAPTER, KEYS (список разделов через запятую). Следуй .claude/agents/verifier.md.
Вход на каждый раздел: build/CHAPTER/course/review-in-KEY.json: список {task, basis_claims}. basis_claims — утверждения автора (страница PDF, текст, цитата), на которых держится ответ. Источник правды: эти утверждения, sections/KEY/units.json и clean.md (для контекста), сканы при сомнении в числах. Своих знаний о геофизике недостаточно для замечания, нужна страница.
Для каждого задания реши, годно ли оно как проверка ПОНИМАНИЯ ПО КНИГЕ:
1. Верность: правильный вариант (answer/answers) действительно следует из basis_claims, а не из знаний модели; условия применимости сохранены; нет переворота знака, сверхобобщения, потери оговорки; нет физической ошибки (критично: неверная физика = снять).
2. Однозначность: ни один неправильный вариант не является верным (или не верен при условиях вопроса); правильный не выделяется длиной/стилем; вопрос не выдаёт ответ.
3. Условие задания понятно новичку без выдуманных чисел; не требует знаний вне basis; сырой TeX нет.
4. expl не противоречит книге.
Решение по каждому заданию: ok | fix (мелкая правка формулировки: дай исправленное задание целиком с теми же id/node/claim/basis) | reject (снять; причина). Не придумывай ошибок: сомнительное, но терпимое — ok с пометкой в notes. Ложные тревоги вредят.
Выход на раздел KEY: build/CHAPTER/course/review-out-KEY.json = {"reject": [{"id":..,"severity":"critical|significant|minor","category":..,"why":..,"page":N}], "fix": [{полное исправленное задание}], "notes": "…"}; остальные ok. Рабочие файлы /tmp/claude-0/rv-<имя>/. Отчёт ≤6 строк: проверено, reject/fix по тяжести, критические.
