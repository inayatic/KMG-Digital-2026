# Промпт стадии «fix_cov» (layer-extractor): ремонт покрытия и целостности слоя одного сегмента
Подставляется: CHAPTER, KEY. Выше перед промптом приведён список проблем сегмента (его выдал tools/check_cov.py). Следуй .claude/agents/layer-extractor.md.

Правишь ТОЛЬКО build/CHAPTER/sections/KEY/{nodes.json, coverage.md, routing.json, report.md}. units.json не трогай. Источник правды: build/CHAPTER/clean.md и units.json сегмента.
По каждой проблеме:
1. «единицы без узла и без причины»: открой текст каждой единицы в units.json. Если это содержательный текст, формула, таблица, подпись рисунка, пример или задача: добавь единицу в unit_ids подходящего существующего узла (и при необходимости утверждение с дословной цитатой на странице единицы), либо создай новый узел по схеме. Если это колонтитул, номер страницы, дубль бегущего заголовка, титул, выходные данные, оглавление, список литературы: добавь строку в coverage.md `| id | тип | стр. | нет узла: <конкретная причина> |`. «Не показуемо» и «не важно» — не причины.
2. «единица в двух узлах»: оставь единицу в одном, наиболее подходящем узле, убери из другого (и удали утверждение, опирающееся только на неё, если оно больше ничем не подкреплено).
3. «узлы без маршрута»: добавь в routing.json объект `{"node": "<id>", "format": "текст|карточки|интерактив|практикум на данных|шортс|длинное видео", "why": "одна фраза"}`. Формат routing.json: JSON-массив таких объектов, без обёртки и без других имён ключей.
4. «нет nodes.json» или «нет единицы»: исправь по смыслу, не удаляя содержательного.
Не меняй id существующих узлов и не удаляй узлы. Не вноси знаний вне книги. Не придумывай причин: каждая причина должна быть верна для конкретной единицы.
