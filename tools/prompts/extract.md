# Промпт стадии «узлы» (layer-extractor), один сегмент главы
Подставляется: CHAPTER, KEY (сегмент), PREFIX (префикс id узлов).

Следуй .claude/agents/layer-extractor.md. Вход: build/CHAPTER/sections/KEY/units.json (единицы сегмента; поле page = PDF-страница), контекст: build/CHAPTER/clean.md, PDF chapters/CHAPTER/*.pdf (сканы: pdftoppm -f N -l N -r 100 -png <pdf> /tmp/x_KEY; читай картинку). Схема: schema/node.draft.json (draft, схемы организаторов нет). Доменного пакета ещё нет.
Выход в build/CHAPTER/sections/KEY/: nodes.json, coverage.md, routing.json, report.md. id узлов: PREFIX.NN-slug (NN сквозной с 01, slug латиницей). order.rank сквозной внутри сегмента.

Обязательные правила (из пилота §12, где verifier нашёл ошибки):
1. Покрытие: каждая единица сегмента ровно в одном узле (unit_ids) ИЛИ в coverage.md с конкретной причиной (титул, колонтитул, список литературы, дубль). «Непоказуемое» не причина. Единицы типов problem/example/table/formula/caption/footnote тоже покрыть.
2. Блоки type=figure_desc — описания рисунков от модели, НЕ слова автора и часто ошибочны (оси, диапазоны, числа). Числа и подписи рисунка бери со скана страницы и текста автора. Число, прочитанное по скану, запиши в ocr_note утверждения («1,0 прочитано по скану»). check_nodes проверяет, что число утверждения author=автор есть в тексте автора на той же странице.
3. Не усиливай автора: сохраняй оговорки («возможно», «как правило», «за исключением…»), диапазоны не заменяй словами («на порядок», «всегда»). Обобщение книги = author: автор только с точной цитатой; своё обобщение = author: модель; догадка/механизм, которого в книге нет = author: гипотеза.
4. Условия применимости: у каждого правила/метода запиши, при каких условиях оно верно (по книге).
5. Порядок терминов: узел с большим order.rank не должен использовать термин раньше узла, где он объяснён; если без этого не обойтись, пометь в layers.nuances «термин объясняется в узле N». Предпосылки из других разделов книги — поле external_prereqs: ["sNN: что нужно"].
6. Типы трудности (М, В, И, Ф, П, Пр, Н, Р) не расшифрованы: ставь по лучшему пониманию, в report.md перечисли, как ты их понял.
7. Арифметические и OCR-огрехи автора не исправляй молча: ocr_note.
8. Задачи книги — в problems (номер, формулировка, нужный рисунок), примеры — в worked_examples (условие, шаги, итог с числами автора). Если ключа ответов в книге нет, не придумывай.
9. Не вноси знаний вне книги. Не зашивай названия глав/страниц в логику.
10. Проверь: python3 -I tools/check_nodes.py build/CHAPTER/sections/KEY/nodes.json build/CHAPTER/sections/KEY/units.json — должно быть errors=0 и uncovered, совпадающий с coverage.md. Исправляй до нуля.
Верни отчёт ≤10 строк: единиц, узлов, ошибок check_nodes, спорное, что требует ментора.
11. Рабочие/промежуточные файлы и генераторы клади ТОЛЬКО в свою папку /tmp/claude-0/work-KEY/ (создай её). Общий scratchpad не используй: параллельные агенты затирают файлы друг друга. Пиши только в build/CHAPTER/sections/KEY/.
12. Формат routing.json СТРОГО: JSON-массив объектов `{"node": "<id узла>", "format": "текст|карточки|интерактив|практикум на данных|шортс|длинное видео", "why": "одна фраза"}`, по одному на каждый узел. Без словаря-обёртки, без других имён ключей (не id и не node_id), без вложенных полей. Если в разделе нет узлов, пиши [].
