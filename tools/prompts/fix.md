# Промпт стадии «fix» (layer-extractor), правка узлов одного сегмента по замечаниям verifier
Подставляется: CHAPTER, KEY.

Следуй .claude/agents/layer-extractor.md. Вход: build/CHAPTER/sections/KEY/verify.md (замечания V-…), ask-mentor.md (вопросы ментору, читай для контекста), nodes.json, units.json, coverage.md, routing.json, report.md. Источник правды: build/CHAPTER/clean.md и сканы PDF chapters/CHAPTER/*.pdf (номера = PDF-страницы; скан: pdftoppm -f N -l N -r 110 -png <pdf> /tmp/claude-0/fwork-KEY/p и прочитай картинку).

Правь ТОЛЬКО build/CHAPTER/sections/KEY/nodes.json (при необходимости coverage.md, routing.json, report.md, если замечание их касается). units.json не трогай.

Правила:
1. Иди по замечаниям по порядку. Для каждого: проверь по источнику (clean.md, при сомнении по скану), что замечание верно. Верно — исправь минимально, по предложению verifier или точнее. Неверно или недоказуемо (уверенность низкая и скана достаточно нет) — НЕ правь, запиши причину в fixes.md.
2. Исправление не должно усиливать автора. Цитата автора только дословная и на своей странице. Если пометка author неверна — поменяй на модель/гипотеза, а не подгоняй цитату. Потерянные оговорки («возможно», «как правило», условия применимости) верни. Число, прочитанное по скану, запиши в ocr_note утверждения.
3. Вопросы из ask-mentor.md НЕ решай сам: там, где ответ нужен ментору, оставь формулировку осторожной и честную (оговорка или ocr_note), не придумывай ответ.
4. Не создавай новых утверждений с author=автор без дословной цитаты. Не вноси знаний вне книги. Порядок терминов (order.rank) не меняй без необходимости; если замечание о порядке, лучше пометь в layers.nuances «термин объясняется в узле N» или добавь external_prereqs.
5. Не переименовывай id узлов и не меняй unit_ids (покрытие должно остаться прежним).
6. Проверка после правки: python3 -I tools/check_nodes.py build/CHAPTER/sections/KEY/nodes.json build/CHAPTER/sections/KEY/units.json — errors=0, uncovered совпадает с coverage.md. Исправляй до нуля. Файл должен оставаться валидным JSON в том же формате (отступ, ensure_ascii=False).
7. Запиши build/CHAPTER/sections/KEY/fixes.md: по каждому V-id одна строка: исправлено (что изменено, где) / не исправлено (почему) / отложено ментору. Правки не пиши в verify.md.
8. Рабочие файлы только в /tmp/claude-0/fwork-KEY/. Пиши только в build/CHAPTER/sections/KEY/.
Отчёт ≤6 строк: замечаний всего, исправлено, не исправлено с причиной, результат check_nodes.
