# Промпт стадии «course v2» (course-builder): задания на ПРИМЕНЕНИЕ правила, раздел KEY
Подставляется: CHAPTER, KEY. Следуй .claude/agents/course-builder.md и правилам tools/prompts/course_tasks.md (формат полей, basis только из утверждений автора, без выдуманных чисел и физики вне книги, ключи только из книги).
Вход: build/CHAPTER/sections/KEY/nodes.json, units.json; сканы по необходимости. Выход: ТОЛЬКО build/CHAPTER/course/tasks2-KEY.json. Рабочие файлы /tmp/claude-0/c2work-KEY/.
ПРОБЛЕМА v1 (новичок-тест): 70–82 % заданий решались поиском ответа в тексте шага: правильный вариант был пересказом утверждения, а вопрос повторял его слова. Цель v2 — задания, где ТЕКСТ ШАГА ДАЁТ ПРАВИЛО, а ответ получается его ПРИМЕНЕНИЕМ к новой ситуации, которой в тексте нет.
Каждое задание ставь в поле "v": 2. Типы (kind):
1. kind:"transfer" (single): конкретная новая ситуация (другие породы/условия/порядок действий/конфигурация, 2–4 предложения, качественно), вопрос «что получится / какой метод применить / можно ли». Верный вариант ОБЯЗАН быть сформулирован своими словами и НЕ содержать 5 слов подряд из текста шага (утверждений и layers) — сборка такие задания отбрасывает. Неверные варианты, наоборот, пересказывай фразами из текста шага (правдоподобные «на слух» ответы): ответ не должен определяться совпадением слов.
2. kind:"diagnose" (single): дано короткое рассуждение или результат с ошибкой (из заблуждений domain-pack/geology/misconceptions.json tier=core или типичная потеря условия); вопрос «какой шаг/допущение нарушает правило» — варианты это шаги рассуждения.
3. kind:"predict" (single|multi): два правила автора (basis из ≥2 разных утверждений) действуют вместе; что произойдёт при совмещении условий.
4. type:"calc2": {id,v:2,type:"calc2",node,claim,q,expr,answer,tol,expl}: формула из утверждения claim (в тексте шага она есть), числа в q ИНЫЕ, чем в примере книги; expr — арифметическое выражение с числами (запятая или точка, только + - * / и скобки), answer — его значение, tol абсолютный. Не используй формулы с OCR-искажением индексов.
Общие правила: 1–3 задания на узел с условием/ограничением/причинной связью; на определения и перечни не делай заданий (там поиск неизбежен); без сырого TeX; q не содержит ответа; варианты 3–4, равной длины; в expl цепочка «правило (c-номер, стр.) → применение к ситуации → вывод»; basis — id утверждений автора (author=автор), 1–3 шт.; claim — одно из basis. Новых физических фактов не вводить: если для вывода нужен факт, которого нет у автора, задания не делай.
Проверка перед выходом: JSON валиден, id вида KEY-v2-NN, у каждого задания поля node (две цифры), claim, basis, v. Отчёт ≤5 строк: заданий по kind, узлов без заданий.
