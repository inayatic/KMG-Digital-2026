# Промпт стадии «course» (course-builder): задания раздела
Подставляется: CHAPTER, KEY. Следуй .claude/agents/course-builder.md.
Вход: build/CHAPTER/sections/KEY/nodes.json (внутренний формат: claims с text/page/quote/author, layers, worked_examples, problems), units.json рядом. Источник фактов только слой; сканы PDF (chapters/CHAPTER/*.pdf) по необходимости.
Выход: ТОЛЬКО build/CHAPTER/course/tasks-KEY.json (создай папку): JSON-список заданий. Рабочие файлы в /tmp/claude-0/cwork-KEY/.
Формат задания (как в tools/course_config/latyshova.json → tasks; ключи «node» — две цифры из id узла, например lat.s12.09-x → "09"; «claim» — id утверждения узла, например "c4"; id заданий "KEY-01", "KEY-02", …):
- single: {id,type:"single",node,claim,q,options[3–5],answer,expl}; answer — один из options и дословная фраза из текста утверждения claim (или ev: дословная фраза из claim, если answer пересказ);
- multi: {…,answers[], options[]}; каждый ответ — дословная фраза из claim;
- blank: {…,q:"Допишите…",text:"…[[слово]]…",answer}; text дословно из claim с вырезанным словом (без чисел-ответов в самом вопросе);
- order: {…,items[],src:"claim"|"example"}; items дословные фрагменты по порядку появления в claim или в шагах worked_examples;
- calc: {…,q,nums[],answer(число),tol,expl}; только если все числа и формула есть в claim/примере книги; nums дословно в claim.
Требования (из теста новичка: задания были «поиск фразы в тексте»):
1. На каждый узел 1–2 задания, всего ≥ 1 задания на каждый узел с утверждениями автора. Приоритет — ПОНИМАНИЕ: вопрос о причине/следствии/условии применимости, «что изменится, если…», «в каком случае метод неприменим», «что здесь вывод, а что допущение». Правильный вариант — формулировка из утверждения; неправильные — правдоподобные искажения (переворот знака, потеря условия, сверхобобщение «всегда», подмена причины), написанные тобой.
2. Формулировка вопроса НЕ содержит ответа и не повторяет его почти дословно. Варианты одной длины и похожи по стилю, правильный не длиннее остальных.
3. Не используй claims с author=модель/гипотеза как основу правильного ответа. Не используй формулы/числа с ocr_note «не использовать в заданиях». Без сырого TeX в q/options: пиши словами и юникодом (η, Δ, ρ).
4. Задачи книги без ключа не превращай в задания; не придумывай ответов. Не ссылайся на узлы вне раздела.
5. expl: одна-две фразы, почему верно; без ссылок на «слой»/«claim».
6. Проверка: python3 -I -c "..." или собственный скрипт: ответы дословно в тексте claim (регистр и пробелы не важны). Исправь до нуля расхождений.
Отчёт ≤5 строк: заданий, по типам, узлов без заданий и почему.
