# Модуль проверки: один срез внешнего пакета
Следуй .claude/agents/verifier.md (категории ошибок, тяжесть, ловушки «верно, но неожиданно»), но вход и выход здесь другие: чужой пакет по схеме организаторов.

Вход (пути абсолютные, подставлены выше строкой SLICE=…, WORK=…):
- `SLICE` — JSON среза: `targets` (цели, которые ты проверяешь, со всеми полями), `context` (связанные утверждения, спецификации сцен — только как контекст, замечания к ним НЕ пиши), `chapter_file` (md главы; номера страниц = метки `<!-- page N -->`), `categories`.
- Кадры (`type: frame`) — PNG по пути `file_abs`: ОТКРОЙ каждый инструментом Read как изображение и сверь то, что видно, с `shows`, `label`, `plaque` и с главой.

СТРОГО: читай только файлы из WORK и chapter_file. Не открывай, не ищи и не запускай ничего с именем key*, score* и файлы вне WORK (кроме .claude/agents/verifier.md). Источник правды только текст главы; своих знаний для вердикта мало, нужна страница главы.

Что делать: для КАЖДОЙ цели из `targets` найди в главе страницу по теме (grep по ключевым словам, затем прочитай страницу целиком) и реши, есть ли в цели ошибка относительно главы. Ошибками заражено около пятой части целей; часть верных целей звучит неожиданно (замечание к ним = ложная тревога, штраф). Типичные закладки: переворот знака/направления (выше↔ниже, рост↔падение, повышает↔понижает), «всегда/любой» вместо условия автора, потерянное условие или оговорка, измеренное↔выведенное (`kind`), неверная степень/зависимость, неверный механизм, старое как текущее, аналогия без границы или с неверной границей (`breaks_where`), для фраз закадра — расхождение с `claim_ref`, для кадров — глубина вверх, газ под нефтью, неверная метка происхождения (симуляция выдана за реальные данные и т. п.), нет плашки о преувеличении, расхождение картинки с описанием и с соседними кадрами/спецификацией.
Сравнивай цель с текстом главы, а не с `quote` цели: цитата может быть верной, а текст цели искажён. Если цель лишь пересказывает главу другими словами без искажения смысла — «ок». Не придирайся к стилю, полноте и мелким упрощениям; замечание только при содержательном расхождении с главой.

Одна ошибка = одно замечание на цель, где она сформулирована; не больше одного замечания на цель. `page_pdf` — страница главы, подтверждающая исправление (для фраз, фактов сцены и кадров — страница утверждения, которое они иллюстрируют). `fix` — исправленная формулировка (что должно быть). `quote` — дословная цитата с этой страницы.

Выход (обязательно оба файла, в WORK):
1. `OUT` (путь подставлен выше) — JSON `{"remarks": [ {"target","category","severity","problem","fix","page_pdf","quote"} ]}`; category строго из `categories`, severity из critical|significant|minor; page_pdf — целое число. Пустой список, если ошибок нет.
2. `NOTES` — по строке на каждую цель: `<id> ок|замечание: почему (стр. N)`.
Перед завершением проверь, что OUT читается как JSON (`python3 -c "import json;json.load(open('OUT'))"`). Отчёт ≤3 строк.
